# ชุดข้อมูลมาตรฐานสำหรับ Dashboard

โฟลเดอร์นี้สร้างจากไฟล์ JSON ต้นฉบับใน `data/` โดยสคริปต์ `data/normalize-data.mjs` และไม่แก้ไขไฟล์ต้นฉบับ

## ไฟล์พร้อมนำเข้า

- `master_offices.json` — ข้อมูลที่ทำการในรูปแบบเดียว พร้อมสถานะพิกัด
- `master_services.json` — ผังบริการและรหัสบัญชี โดยคง Text Code `COD_FEE`, `DIT`, `e-Commerce`, `Fuze`, `สลาก` เป็น ID ของบริการเช่นเดียวกับรหัส SAP
- `transactions_monthly.json` — รายการ SAP, BI และแหล่งเสริมในโครงสร้างเดียว
- `targets.json` — เป้าหมายที่แปลงชื่อฟิลด์และชนิดข้อมูลแล้ว
- `transactions_daily.json` — ข้อมูล รส.201/Pickup พร้อมวันที่ ISO และช่วงสัปดาห์ศุกร์–พฤหัส
- `transactions_weekly.json` — ข้อมูลรายวันรวมตามช่วงสัปดาห์ สำหรับ API รายสัปดาห์
- `weekly_targets.json` — เป้าหมายรายสัปดาห์และเป้าหมายสะสมระดับหมวดหมู่
- `data_quality_report.json` — ผลการตรวจสอบการอ้างอิง Master

## กติกาที่นำไปใช้

- ข้อมูลจัดเก็บปี ค.ศ.; หน้าจอจะแปลงปีที่เลือกจาก พ.ศ. ด้วย `CE = BE - 543`.
- BI ที่ไม่ระบุ `category` ถือเป็น `REVENUE`; รายการที่ระบุ `ค่าใช้จ่าย` เป็น `EXPENSE`.
- `ปข.6` ของ BI ถูกเชื่อมกับ `60000-00` (สำนักงานไปรษณีย์เขต 6); `รายได้อื่น` เป็นก้อนสรุปที่นับใน BI Summary แต่ไม่ปรากฏบนแผนที่.
- รายสัปดาห์เริ่มวันศุกร์และจบวันพฤหัส โดยคงทั้ง `date`, `weekStart`, `weekEnd` เพื่อคำนวณ Target เฉพาะจำนวนวันในเดือนจริงได้.

## รายการที่ยังต้องยืนยันก่อนเปิดใช้แผนที่

1. `master_post.json` ไม่มีพิกัด จึงตั้ง `coordinates` เป็น `null` และยังไม่ควรวาดหมุด/พื้นที่เชิงภูมิศาสตร์จนกว่าจะมีพิกัดหรือ GeoJSON ที่เชื่อถือได้
2. Pickup และ รส.201 แสดงยอดตามบริการ/กลุ่มธุรกิจได้ตามจริง แต่ไม่ถูกจับคู่ Target รายบริการ: การเทียบเป้าใช้ยอดรวม รส.201 + Pickup กับ `weekly_targets.json` ระดับหมวดหมู่รายได้
3. `weekly_targets.json` มีทั้ง Target เฉพาะงวด (เช่น 23.33%) และ Target สะสมถึงสิ้นงวด (เช่น 46.67% เมื่อผ่าน 14 วันของเดือน 30 วัน)
